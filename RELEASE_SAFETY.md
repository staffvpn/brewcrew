# Тестовая кофейня и выпуск обновлений

## Где проверять

- Стабильная игра: https://brewcrew.pages.dev/
- Админская тестовая кофейня текущей версии: https://brewcrew.pages.dev/lab/. Ссылка открывается через Telegram.
- Будущие обновления: ветка `staging`, адрес Cloudflare Pages `https://staging.brewcrew.pages.dev/`, с branch preview Cloudflare Pages; кнопка «Тестовая кофейня» в `/admin` ведёт сюда. Публикация этой ветки не меняет `main`.

Это отдельная игровая среда, а не отдельная физическая база: сервер использует только ключи `lab_v1_<admin-id>` в `cache`. Если у preview нет секретов бота, его запросы перенаправляются на фиксированный адрес рабочего сервера с обязательным заголовком тестовой среды: там они проходят тот же изолированный обработчик. Рабочие API при этом не вызываются. Все API тестовой среды перехватываются до рабочих обработчиков. Обычные игроки не проходят серверную проверку подписанного Telegram ID. Платежи, подарки игрокам, посещения, рассылки, вебхук и настройка бота из preview запрещены. Не добавлять в sandbox вызовы рабочих обработчиков с `env.DB`.

LocalStorage теста имеет префикс `bc_lab_v1_`. Telegram CloudStorage в тесте полностью отключён, потому что он общий для бота даже на разных доменах. В тестовую кофейню не импортируются рабочие сохранения админа. Тестовые покупки бесплатны. Пропуск открыт админам на все 50 ступеней.

## Порядок выпуска

1. Разрабатывать и публиковать в `staging`. Проверять тестовую кофейню через Telegram, затем выполнять профильные проверки из `tests/`.
2. До выпуска проверять загрузку **копий** старых сохранений: улучшения, сезон и забранные награды, инвентарь, сотрудники, рефералы. Не изменять версию ключа хранения и не использовать сброс как миграцию.
3. Когда версия проверена, включить «Техработы» в админке. Сервер в одной транзакции делает неизменяемые копии текущих полных сохранений (`release_backup:<timestamp>:full_save_<id>_current`) и включает флаг. Они не заменяют поколения `current/previous`.
4. Для изменений схемы базы дополнительно сделать полный экспорт D1 средствами Cloudflare. Снимки в `cache` сохраняют кофейни, но **не являются полным экспортом таблиц платежей, рефералов и админских команд**.
5. Перенести проверенные коммиты в `main`, дождаться успешного Cloudflare deploy. Проверить API и восстановление старой кофейни; не удалять покупки, сезонные права, приглашения и очереди команд.
6. Выключить техработы. Проверка статуса в открытой новой версии идёт раз в 15 секунд. Старая открытая вкладка может проверять раз в минуту, поэтому для первого перехода следует дождаться остановки старых клиентов.

Рабочая игра проверяет техработы до восстановления сохранения. При активной паузе экран создания новой кофейни не открывается. При недоступном сервисе статуса игра ждёт соединения, сохраняя данные. Сервер блокирует изменяющие POST-запросы игроков, включая сохранения и счета. Интервалы паузы хранятся постоянно и вычитаются при расчёте отсутствия; продажи, зарплаты и налоги за паузу не симулируются. Игровые таймеры и цикл сцены также приостанавливаются. Админы в рабочей игре освобождены от техработ; для проверки новых функций использовать тестовую среду.

При проблеме оставить техработы, вернуть предыдущую версию приложения и разобраться с конкретными копиями. Не восстанавливать всем игрокам старую базу целиком: это может откатить законные покупки. Автоматического сброса аккаунтов при ошибке загрузки нет.

## Проверки

`node tests/sandbox-maintenance.mjs`

`NODE_PATH=/tmp/brewcrew-qa/node_modules node tests/sandbox-browser.cjs`

`NODE_PATH=/tmp/brewcrew-qa/node_modules node tests/badges-pause-browser.cjs`

Браузерные проверки используют HTTP-сервер в корне проекта на порту 8770, Chromium и подменённые API. Реальных списаний и записей игрокам не делают.
