# Brew Crew

Telegram Mini App: симулятор кофейни с реальной экономикой, командой, проверками и абсурдными событиями. 18+.

- `index.html` и `sprites.png` — сама игра, без сборки.
- `functions/` — серверная часть на Cloudflare Pages Functions:
  - `POST /api/track` — игра раз в минуту отмечает игрока (подпись Telegram проверяется на сервере);
  - `POST /tg/webhook` — бот: `/start` и `/admin` (только для админов из `functions/_lib.js`);
  - `GET /tg/setup?key=WEBHOOK_SECRET` — один раз подключает вебхук и кнопку меню.
- `wrangler.toml` — привязка базы D1 `brewcrew` как `DB`.

Секреты задаются в Cloudflare Pages → Settings → Variables and Secrets: `BOT_TOKEN`, `WEBHOOK_SECRET`. В репозиторий их не кладём.

Магазин использует Telegram Stars (`XTR`). Постоянные товары описаны в `functions/_store.js`, остальные — в `SHOP` из `functions/_lib.js`. Таблица `SHOP_PRICES.csv` содержит прежние и новые цены. При изменении каталога нужно обновлять встроенный `BC_STORE` в `index.html`: тест проверяет совпадение. Способ «За деньги» пока отключён. Сервер выдаёт новые предметы по подтверждённым платежам, админам — через проверяемые тестовые покупки.

`POST /api/cafes` возвращает три кофейни или результаты поиска по названию (12 за страницу). `POST /api/cafeview` отдаёт общедоступную обстановку и принимает респект раз в день. Снимки обновляются при трекинге; просмотр запускает отдельную визуальную сцену без экономических действий. Пока хозяин не прислал снимок, показывается сообщение об этом.

Проверки: `node tests/shop-visits.mjs` (Node 24+, SQLite; все платежи и Telegram-запросы подменены). Для проверки интерфейса установите Playwright, запустите HTTP-сервер из корня проекта на порту 8770 и выполните `node tests/shop-visits-browser.cjs`, затем ту же команду с `--admin`. Проверка использует Chromium `/usr/bin/chromium`; реальные списания не запускаются.

Админка бота открывается командой `/admin` и доступна только ID из `ADMINS`. Главный экран сокращён до управления игроками и основных показателей; публикации, рефералы и акции находятся в «Дополнительно». Раздел «Имущество» содержит текущий каталог магазина, награды, команду, инвентарь, значки, ресурсы и улучшения. Изменение требует подтверждения конкретного игрока и объекта. Повторное подтверждение не создаёт вторую операцию; действия сохраняются в `admin_ops` и применяются игрой при следующем трекинге.

Изъятие платного предмета хранится отдельно в `cache` (`admin_entitlements_<id>`) и не изменяет историю платежей или признаки возврата Stars. Выдача восстанавливает доступ. Личные сотрудники и инвентарь берутся из ограниченного снимка `admin_inventory_<id>`; он недоступен через публичные посещения. Для ранее не заходившего после обновления игрока личный инвентарь появится после его следующего входа.

Кнопки, заголовки и значки в тексте админки используют точные ID из `tgiosicons`, закреплённые по названию в `functions/_admin-icons.js`. Источник метаданных — публичный каталог https://emoji.wivvi.net/emoji.json. Автоподбор по обычным эмодзи и старый кэш больше не используются: одному Unicode-эмодзи в наборе соответствует несколько разных рисунков. Пункт «Иконки tgiosicons» в дополнительных инструментах показывает реальные выбранные значки и последнюю ошибку Telegram, если оформление было отклонено. Отдельно обрабатываются ограничения на custom emoji в подписи и на кнопках.

Построенные расширения нельзя уменьшить через магазин. Новый старт и продажа кофейни дают обычный зал; лицензии на купленные расширения позволяют построить их повторно бесплатно. Момент покупки передаётся вместе с правами, чтобы старые покупки не расширяли новую кофейню автоматически.

Дополнительные проверки: `node tests/admin-assets.mjs`, `node tests/admin-assets-browser.cjs` (тот же Playwright и HTTP-сервер, что для проверки магазина). Проверяются подтверждения и доступ администратора, выдача и изъятие, повторные запросы, восстановление прав, деньги и скоропортящиеся продукты, сотрудники и инвентарь, неизменяемые расширения, новый старт и настоящая продажа кофейни.

Новые команды имущества выдаются только клиентам с `adminProtocol: 1`: старая открытая версия игры не сможет подтвердить и потерять неизвестную ей команду. До обновления клиента команда останется в очереди.

Админские панели отправляются одним `sendPhoto` с `caption` и `reply_markup`. Переход в раздел выполняет `editMessageMedia` того же сообщения; страницы длинного отчёта — `editMessageCaption`. Подписи делятся без потери текста, с сохранением целых custom emoji и сбалансированных HTML-тегов; страницы привязаны к администратору, чату и сообщению. Старая отдельная обложка удаляется по сохранённому ID при следующем открытии панели.

Для админки созданы 18 новых широких баннеров в `img/admin/`; старые `hall.jpg`, `expand.jpg` и прежний `admin-banner.png` в панелях не используются. Проверка оформления: `node tests/admin-presentation.mjs`.
